# WebShop 信用门控干预：离线回放与最小训练验证

日期：2026-11-11（America/Los_Angeles）。用户输入为选定方案 B 的粘贴文本。实现基准为 WebShop R2 对齐版冻结运行，逐模块 SHA-256 保存于 baseline_manifest.json；继续核对指定 GitHub 提交。

本次实现三个可独立开关的机制，不将组合称为单机制消融：

- E：格式异常或语义 noop 的辅助差分与 GAE 结果为零，不参与信用桶，不改变实际动作执行、状态解析、格式标签或原生奖励。
- N：合法 item/detail → home/results 返回导航的辅助项规则。用户文本的单步差分截断与 raw==0 断言不等价，因此实现两种明确模式用于离线比较：negative_delta_clip 仅截断负差分，neutral 切断自身向后 GAE、退出信用桶并置 raw/centered 为零。用户已选择 neutral，训练固定使用该模式。
- B：已终止的可执行 Buy Now 在全败组中辅助信用为零并退出桶，原生环境奖励与原生 GiGPO 优势保持原实现。

不添加重复搜索、详情页点击等新 noop 启发式；原文所引用的 build_episode_step_records 并非当前 adapter 的函数，按实际 parse_trace 接口实现。保留 semantic noop 和 format validity 为两个独立观测量。中心化仍作用于传播后的原始辅助信用，不错误地改成仅中心化单步 delta。先按原锚点构桶，再在每桶剔除被门控动作；不因有效成员变少而引入新的跨状态 fallback 混合。有效成员不足两条时仍遵守原零信用规则。

## 假设及竞争解释

H1：辅助项正奖励格式异常、对返回与终止购买的桶残差，影响了后期行为。H0：退化由原生更新、策略泛化、此前累积或其他机制导致；把这些辅助项归零能满足定义，但不一定改善策略。

离线回放只验证执行语义和信号差异。既有轨迹是在旧策略下采样，离线断言通过不能证明新策略成功率改善。全败组未成功购买不等于购买了错误商品类别；训练使用的成功奖励与诊断任务分数分开，格式惩罚系数仍为 0.1。

## 零 GPU 运行范围

在旧版与对齐版各 150 轮、各 19,200 条真实训练轨迹上，对齐版基准及 E/N/B 各自、组合逐轮回放。旧版轨迹使用对齐版核心是反事实回放，不称为原旧版算法重现。对齐版关开关结果须与冻结对齐版全部信用输出、诊断和历史表一致；两份原轨迹的流式 SHA-256 必须匹配前次审计。

主要断言：格式异常及 semantic noop 的正信用数为零；终止购买辅助信用严格为零；neutral 返回的 raw 与 centered 严格为零；样例 C 的同伴桶满足以上规则。严格按原始动作集合比较，不通过重新命名 noop 隐藏原 10,247 个 format_invalid_not_noop；此前严格 >0 的计数与 >1e-12 分开。

补充必要检查：未门控的有效进展仍可能获得非零信用；非全败组辅助信用恒零；历史/表/状态不因门控变化；中心化有限且有效桶内和近零；token 映射后的门控动作仍为零。报告新归一化的正确 token 幅度需要实际 response mask，离线缺失该项时不复用旧 scale 冒充真实新注入。
